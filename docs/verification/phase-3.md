### Findings from the automated pass

1. No defects found. The suite size matched the brief's estimate exactly (175), unlike phases 1–2 where the count drifted upward.
2. The per-app UI save was driven through the Apps tab's plain buttons because synthetic AX picks on the toolbar's "Navigation Tab Bar" tab items are unreliable: AXPress/AXPick on those menu items return success but only land when the app happens to be active, sometimes minutes later. Tab switching eventually worked (Apps and Devices tabs were reached and read back live), and plain `Button`s ("Add Frontmost App", the row trash) respond to AXPress on the first try — worth knowing for future automation passes. Visual confirmation of the tab strip remains a human item below.
3. "Add Frontmost App" recorded the frontmost bundle ID as `app.artmouse` (artMouse's own Settings window was the most recently active app during the pass). This is an automation-context artifact, not a bug — the row was deleted immediately and the human per-app checks below use real front apps.
4. During the tab-navigation attempts the Settings window closed once unexpectedly (it was reopened via the status menu). Likely a stray synthetic pick hitting the close button; no crash (same PID 42190 kept running). Noted for AX-automation hygiene, not an app defect.

- [ ] Permissions: fresh TCC state → banner shows, Grant button opens the right panes; after granting, macro/snapping/per-app features work without relaunch.
  HOW TO VERIFY: remove artMouse from System Settings → Privacy & Security → Accessibility and Input Monitoring, launch the app and confirm the banner (observed present during the automated pass), click Grant for each row, approve both panes, then trigger a bound macro — it must work with no relaunch.
- [ ] Macro sequence: bind a macro (Key k, Wait 250, Key s) to the 4th button; press it in TextEdit — "ks" types after 250 ms.
  HOW TO VERIFY: in Settings → Buttons bind the 4th button to Macro with steps Enter k → Wait 250 ms → Enter s (repeat mode None), click into TextEdit, press the 4th button — the letters "ks" must appear, with the "s" landing about 250 ms after the "k".
- [ ] Macro hold-repeat: repeat mode Hold, interval 250; hold the button — the sequence repeats until release; no stuck key afterwards.
  HOW TO VERIFY: set the macro's repeat mode to Hold with interval 250, hold the 4th button in TextEdit for ~2 s — "ksksks…" must keep typing while held and stop immediately on release, with no key left stuck (subsequent typing is normal).
- [ ] Modifier proxy: hold ⌘ physically, trigger the macro — the macro's keys register as ⌘+key.
  HOW TO VERIFY: with the macro bound and its Modifier Proxy enabled, hold the physical ⌘ key and press the macro button in TextEdit/Safari — the macro's keys must land as ⌘-modified (e.g. ⌘K/⌘S behaviors), matching whatever modifier you actually hold.
- [ ] Snapping: open a dialog with a default button; bind Snap (click on) — cursor jumps to the default button and clicks it.
  HOW TO VERIFY: in Settings → Buttons bind the 4th button to Snap with Click on, focus a window whose default (highlighted) button is visible (e.g. a save dialog), move the cursor far away, press the button — the cursor must jump to the default button and click it.

  HOW TO VERIFY: set Snap to click + bounce on, note the cursor position, press the button over a dialog — the default button must be clicked and then the cursor must return to the exact starting point.
- [ ] Snapping no-op: focus a window with no default button — nothing happens, cursor stays.
  HOW TO VERIFY: focus a window without a default button (e.g. a plain TextEdit window), press the Snap button — the cursor must not move and no click must be synthesized.
